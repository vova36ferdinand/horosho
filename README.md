# Учебное задание — вариант 15

Программа на Python для работы с аккаунтами, сообщениями и обратной связью.
Данные хранятся в памяти процесса и очищаются после его завершения.
Реализованы интерактивное меню, TCP RPC-сервер, клиент и модельные тесты.

Условия сверены с вариантом №15 сборника индивидуальных заданий,
страницы 48–50. Записи хранятся **кортежами** в порядке полей ER-диаграммы:

| Сущность | Поля кортежа |
| --- | --- |
| Account | `uid, timestamp, ip` |
| Message | `uid, timestamp, argument, account, completed` |
| Feedback | `uid, timestamp, result, status, failure, message` |

Каждая сущность поддерживает создание, получение всех записей,
получение по ID и редактирование. Создание существующего ID заменяет
его запись; чтение или обновление отсутствующего ID возвращает `None`.
В JSON-ответах кортежи передаются как массивы, а `None` — как `null`.

## Выборка по формуле

```text
π_{A.ip, M.argument}(σ_{A.timestamp ≥ now − 8 min}(A ⟗_{A.uid = M.account} M))
```

Знак `⟗` означает **полное внешнее соединение**. Реализация сначала
соединяет Account и Message, затем фильтрует по времени **аккаунта**,
после чего оставляет уникальные пары `(IP, текст сообщения)`.

- Граница `now − 8 * 60` включается благодаря `≥`.
- Свежий аккаунт без сообщений даёт `(ip, None)`.
- Сообщение без аккаунта отбрасывается: `A.timestamp` у него отсутствует.
- Дубли одинаковых пар удаляются, даже если исходные ID различаются.
- Время самого сообщения и поле `completed` на выборку не влияют.
- Верхней границы `timestamp ≤ now` в формуле нет.

Например, при `now = 4000` аккаунт `(1, 3520, "192.0.2.1")`
без сообщений возвращает `[("192.0.2.1", None)]`.

## Требования

Python 3.10 или новее. Основная программа использует стандартную библиотеку.
Для тестов и проверок установите зависимости из корня репозитория:

```console
python -m pip install -r requirements-dev.txt
```

В Windows вместо `python` можно использовать `py`.

## Интерактивное меню

```console
python src/repl.py
```

Команды 1–4 создают, перечисляют, находят и обновляют аккаунты;
5–8 выполняют эти операции для сообщений; 9–12 — для Feedback.
Меню запрашивает все поля записи, включая целочисленное Unix-время
в секундах. Команда 13 выполняет выборку по приведённой выше формуле.
Команда 0 завершает программу.

Меню обращается к локальному слою данных напрямую. Сервер для него не нужен;
данные меню и отдельно запущенного RPC-сервера хранятся раздельно.

## RPC-сервер и клиент

Для работы через сервер откройте два терминала в корне проекта.
В первом запустите сервер:

```console
python src/rpc_server.py
```

Во втором запустите Python-файл клиента, который демонстрирует все
13 операций задания на запущенном сервере:

```console
python client.py
```

В Windows команды выглядят так: `py src/rpc_server.py` в первом окне,
`py client.py` — во втором. Вводите их в командной строке `C:\...>`,
а не внутри Python с приглашением `>>>`.

Python-код примера находится в функции `demonstrate` файла `client.py`.
Вызовы `client.create_account(...)`, `client.create_message(...)` и другие
отправляют RPC-запросы; функции слоя данных выполняются в процессе сервера.
Скрипт выводит результаты всех операций и завершается. Сервер продолжает
работать, а его данные доступны следующим клиентам. Повторный запуск
обновляет демонстрационные записи с ID 1.

Для другого адреса: `python client.py --host 127.0.0.1 --port 8080`.

При необходимости можно запустить интерактивное меню клиента:

```console
python src/repl.py --rpc
```

В Windows можно дважды щёлкнуть `run_server.bat`, затем `run_rpc.bat`.
Если сервер уже работает, достаточно запустить `run_rpc.bat`.
В RPC-режиме все 13 команд меню работают с данными процесса сервера,
включая записи, созданные другими клиентами. Выход из меню командой 0
закрывает только клиент; сервер останавливается Ctrl+C в его окне.

Адрес по умолчанию — `127.0.0.1:8080`. Другой адрес указывается так:

```console
python src/repl.py --rpc --host 127.0.0.1 --port 8080
```

При недоступности сервера меню сообщает об ошибке и принимает следующую
команду. Для удалённого подключения сервер должен слушать адрес,
доступный клиенту; стандартный запуск предназначен для одного компьютера.

Пример программного клиента из корня проекта:

```python
import time
from src.rpc_client import RPCClient

client = RPCClient()
now = int(time.time())
client.create_account(1, now, "127.0.0.1")
client.create_message(1, now, "Привет!", 1, 0)
client.create_feedback(1, now, "ok", "sent", "", 1)
print(client.select_recent_messages(now))
```

Каждый запрос передаётся через отдельное TCP-соединение. Заголовок состоит
из 3 байт длины JSON-тела в порядке little-endian и 1 байта кода операции.
Тело кодируется в UTF-8. Коды 1–13 соответствуют пунктам меню.
Ответ содержит тот же код операции и JSON с полем `result`.
Сервер записывает запросы в `journal.log` в текущей рабочей папке.

## Тестирование и стиль

```console
python -m pytest -q
python -m coverage run --branch --source=src --omit="src/repl.py,src/__init__.py" -m pytest tests/test_mbt.py
python -m coverage report -m
python -m pycodestyle src tests
python -m radon cc src tests -s
```

Отдельный запуск `tests/test_mbt.py` формирует покрытие только тестами,
сгенерированными `hypothesis.RuleBasedStateMachine`, согласно этапу 3.
Каждый пример проверяет все 13 методов через настоящий TCP-сервер,
затем выполняет случайные последовательности операций. Выборка
сравнивается с независимым SQL-запросом в изолированной БД в памяти.
Сохранённый отчёт — `docs/mbt-coverage.txt`.

Дополнительные тесты проверяют все команды меню, ошибочный ввод,
хранение кортежей, повторное создание после обновления, точную границу
восьми минут, отсутствующие связи, дубликаты, формат RPC и журнал запросов.
Тестовый сервер запускается автоматически на свободном локальном порту.

В Windows `run.bat` запускает модельные тесты с отчётом покрытия,
остальные тесты и меню.
В Linux/macOS после установки зависимостей выполните `bash run.sh`.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/data_layer.py` | Хранение данных и операции с записями |
| `src/repl.py` | Интерактивное меню |
| `src/rpc_server.py` | Приём и обработка RPC-запросов |
| `src/rpc_client.py` | Клиент RPC-сервера |
| `client.py` | Запуск Python-кода с демонстрацией 13 операций через RPC |
| `tests/` | Модельные и регрессионные тесты |

Функции ограничены 40 строками, обычные комментарии в Python заменены
документирующими строками. Сообщения коммитов используют формат
`type(scope): description`, например `fix(repl): simplify command dispatch`.
